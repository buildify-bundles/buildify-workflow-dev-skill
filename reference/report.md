# 汇报格式：保存、试跑、发布

字段一律取**这一次**命令的返回，不要为了填表再请求。刚 `deploy --wait` 完不要调 `workflow published`；用户事后问线上版本时才用它画同一套表。

## 通用规则

- 概览和**服务器都用 Markdown 表**，服务器表列：服务器、描述、在线、部署、说明。不要改成列表。
- 标题可用彩色 emoji（`## ✅ 已发布`）。**表格单元格不要写** `🟢` `✅` `❌` 这类彩色 emoji：很多客户端（含 Cursor）在表里不渲染，看起来像丢了。单元格用下文的符号 + 中文。
- 只用名称（项目名、流程名、版本名、`workerName`），不要甩 projectId / workerId / deploymentId，除非用户要排障。
- 不要输出节点信息（链路、节点表、`label` / `summary` / 触发类型 / `webhookPath`），响应里有 `summary.nodes` 也忽略。HTTP 接口的访问地址例外。

## 保存草稿后

```markdown
## 已保存

| 项 | 内容 |
| --- | --- |
| 项目 | 测试项目 |
| 流程 | 当前时间 API |
| 服务器 | 本地java进程测试 |
```

## 试跑后

标题写「试跑通过」或「试跑未通过」，「结果」写一句结论，不贴节点输出。HTTP 接口加「测试地址」（带 `/@test`）和「HTTP 状态」两行；访问地址不通时不出这张表，改用 SKILL「试跑 HTTP 接口」第 3 步的提示。

```markdown
## 试跑通过

| 项 | 内容 |
| --- | --- |
| 项目 | 测试项目 |
| 流程 | 当前时间 API |
| 服务器 | 火山测试服务器 |
| 测试地址 | `GET http://1.2.3.4:8080/@test/test2` |
| HTTP 状态 | 200 |
| 结果 | 返回了当前时间 |
```

## 发布后

```markdown
## ✅ 已发布

| 项 | 内容 |
| --- | --- |
| 项目 | 测试项目 |
| 流程 | 当前时间 API |
| 版本号 | `v20261005-184620` |
| 发布说明 | 首次上线 /test2 当前时间接口 |
| 总体 | ✓ 成功 |
| 发布时间 | 2026-09-21 09:30:00 |
| 访问地址 | `GET http://1.2.3.4:8080/test2` |

### 服务器

| 服务器 | 描述 | 在线 | 部署 | 说明 |
| --- | --- | --- | --- | --- |
| 本地java进程测试 | 测试专用 | ● 在线 | ✓ 成功 | — |

### 凭证

未引用访问凭证
```

「访问地址」只在 HTTP 接口时写，用**正式地址**（不带 `/@test`），多个接口每个一行；没有 `externalHost` / `httpPort` 时写「服务器访问地址 + `/test2`」，并提示到「节点管理」设置。

有凭证时「凭证」下只出这张表：

```markdown
| Bundle | 类型 | 名称 |
| --- | --- | --- |
| official/mysql | Mysql | 生产只读 |
```

本次编排中途新开发并发布了 Bundle 时，在「凭证」前加一节「新增 Bundle」，每个包一行：

```markdown
### 新增 Bundle

| Bundle | 版本 | 用到的节点 |
| --- | --- | --- |
| acme/order-sync | 1.0.0 | 同步订单 |
```

## 状态映射

按 `deployStatus` / `isOnline`（或 `deployStatusLabel` / `onlineLabel`）映射，**不要**把响应里的 `deployStatusIcon` / `onlineIcon` 原样贴进表格。

| 含义 | 标题 | 表格单元格 |
| --- | --- | --- |
| 成功 | `## ✅ 已发布` | `✓ 成功` |
| 成功有警告 | `## ⚠️ 已发布（有警告）` | `! 有警告` |
| 失败 | `## ❌ 发布失败` | `✗ 失败`，说明列写 `message` |
| 超时 | `## ⏰ 发布超时` | `… 超时` |
| 部署中 / 待部署 | `## 🔄 发布中` | `… 部署中` / `… 待部署` |
| 已取消 | `## 🚫 已取消` | `✗ 已取消` |
| 在线 / 离线 | （写在服务器表） | `● 在线` / `○ 离线` |

失败示例：

```markdown
## ❌ 发布失败

| 服务器 | 描述 | 在线 | 部署 | 说明 |
| --- | --- | --- | --- | --- |
| mac | 无描述 | ○ 离线 | ✗ 失败 | connection refused |
```
