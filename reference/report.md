# 汇报格式：保存、试跑、发布

字段一律取**这一次**命令的返回，不要为了填表再请求。发布表直接用 `scripts/result.mjs deploy deploy.json` 打印的版本号、说明、总体状态、服务器行和凭证显示名。刚 `deploy --wait` 完不要调 `workflow published`，也不要拉 `workflow deployments`；用户事后问线上版本时才用 `published` 画同一套表。问过去的发布或历史版本时见「事后查询」。

## 通用规则

- 概览、**服务器**、**凭证**都用 Markdown 表，不要改成列表。两节都要有，只写主要信息。
- 服务器表列：服务器、状态。描述有内容写在名称后的括号里（`本地java进程测试（测试专用）`），没有描述不加括号，也不要写「无描述」。保存和试跑还没有部署结果，状态只写 `● 在线` 或 `○ 离线`。发布后把部署结果接在后面，如 `● 在线 · ✓ 成功`。`message` 为空或就是 `—` 时不加「说明」列；某台失败、有警告、超时或离线且有 message 时才加，写原文。
- 凭证表只一列「凭证」，写这次已经绑上的显示名（`displayName`；1.4.x 是 `label`），多条就多行。不要为了填表再查接口。不写 Bundle 包名，不写 `FeishuBotCredentials` 这类类型名。没有凭证时不列表，写「未引用访问凭证」。
- 概览表不单列「服务器」，避免和下面的服务器节重复。
- 标题可用彩色 emoji（`## ✅ 已发布`）。**表格单元格不要写** `🟢` `✅` `❌` 这类彩色 emoji：很多客户端（含 Cursor）在表里不渲染，看起来像丢了。单元格用下文的符号 + 中文。
- 只用名称（项目名、流程名、版本名、`workerName`、凭证显示名），不要甩 projectId / workerId / deploymentId，除非用户要排障。
- 本机有多个工作区（prepare 写了「本机共 N 个工作区」）时，概览表在「项目」上方加一行「工作区」，写显示名（带「」的那个）；没有显示名才写 profile 名。只有一个工作区时不写。
- 新建流程、或从别的项目复制过来后的第一张表，「项目」写成「名称（新建于此）」或「名称（从 原项目 复制）」，让用户一眼看到流程落在哪。
- 不要输出节点信息（链路、节点表、`label` / `summary` / 触发类型 / `webhookPath`），响应里有 `summary.nodes` 也忽略。HTTP 接口的访问地址例外。

## 保存草稿后

```markdown
## 已保存

| 项 | 内容 |
| --- | --- |
| 项目 | 测试项目 |
| 流程 | 当前时间 API |

### 服务器

| 服务器 | 状态 |
| --- | --- |
| 本地java进程测试（测试专用） | ● 在线 |

### 凭证

| 凭证 |
| --- |
| 代码记忆测试机器人 |
```

## 试跑后

标题写「试跑通过」或「试跑未通过」，「结果」写一句结论，不贴节点输出。HTTP 接口加「测试地址」（带 `/@test`，用实际测通的地址）和「HTTP 状态」两行；候选地址都不通时不出这张表，改用 [http.md](http.md)「试跑 HTTP 接口」第 3 步的提示。「结果」和失败节点从 `scripts/result.mjs test-run` 的摘要里取。

```markdown
## 试跑通过

| 项 | 内容 |
| --- | --- |
| 项目 | 测试项目 |
| 流程 | 当前时间 API |
| 测试地址 | `GET http://1.2.3.4:8080/@test/test2` |
| HTTP 状态 | 200 |
| 结果 | 返回了当前时间 |

### 服务器

| 服务器 | 状态 |
| --- | --- |
| 本地java进程测试（测试专用） | ● 在线 |

### 凭证

| 凭证 |
| --- |
| 代码记忆测试机器人 |
```

## 发布后

```markdown
## ✅ 已发布

| 项 | 内容 |
| --- | --- |
| 项目 | 测试项目 |
| 流程 | 当前时间 API |
| 版本号 | `v20261005-184620` |
| 发布说明 | 首次上线 /test2 当前时间接口 |
| 总体 | ✓ 成功 |
| 发布时间 | 2026-09-21 09:30:00 |
| 访问地址 | `GET http://1.2.3.4:8080/test2` |

### 服务器

| 服务器 | 状态 |
| --- | --- |
| 本地java进程测试（测试专用） | ● 在线 · ✓ 成功 |

### 凭证

| 凭证 |
| --- |
| 代码记忆测试机器人 |
```

「访问地址」只在 HTTP 接口时写，用**正式地址**（不带 `/@test`），多个接口每个一行。地址用试跑时实际测通的那个（登记地址、公网 IP、默认端口或用户给的），和控制台登记的不同时，表下加一句「控制台登记的地址不通，这次用的是 …」，并提示到「节点管理」修改。没有测通过的地址时写「服务器访问地址 + `/test2`」，并提示到「节点管理」设置。没有凭证时，「凭证」下写「未引用访问凭证」，不要出空表。

本次编排中途新开发并发布了 Bundle 时，在「凭证」前加一节「新增 Bundle」，每个包一行。「新建」表示本次创建了软件包，只在已有包里加节点时写「已有」：

```markdown
### 新增 Bundle

| Bundle | 显示名 | 版本 | 可见性 | 软件包 | 用到的节点 |
| --- | --- | --- | --- | --- | --- |
| acme/order-sync | 订单同步 | 1.0.0 | 工作空间内可用 | 新建 | 同步订单 |
```

可见性 `internal` 写「工作空间内可用」，`restricted` 写「受限」。

## 状态映射

按 `deployStatus` / `isOnline` 枚举映射（CLI 1.3.0 起响应里不再带图标和中文标签）。`deployStatus` 取值：`success` 成功、`success_with_warnings` 有警告、`failed` 失败、`timeout` 超时、`running` 部署中、`pending` 待部署、`canceled` 已取消。`result.mjs deploy` 已按下表换好。

| 含义 | 标题 | 表格单元格 |
| --- | --- | --- |
| 成功 | `## ✅ 已发布` | `✓ 成功` |
| 成功有警告 | `## ⚠️ 已发布（有警告）` | `! 有警告` |
| 失败 | `## ❌ 发布失败` | `✗ 失败`，说明列写 `message` |
| 超时 | `## ⏰ 发布超时` | `… 超时` |
| 部署中 / 待部署 | `## 🔄 发布中` | `… 部署中` / `… 待部署` |
| 已取消 | `## 🚫 已取消` | `✗ 已取消` |
| 在线 / 离线 | （写在服务器「状态」列） | `● 在线` / `○ 离线` |

发布后的状态列把在线和部署拼在一起，如 `● 在线 · ✓ 成功`。`result.mjs deploy` 已按这个格式打印服务器行和凭证显示名。

失败示例：

```markdown
## ❌ 发布失败

### 服务器

| 服务器 | 状态 | 说明 |
| --- | --- | --- |
| mac | ○ 离线 · ✗ 失败 | connection refused |
```

## 事后查询

用户问部署记录或历史版本时才出这些表。状态符号用上面的映射，单元格仍不放彩色 emoji。不写 `deploymentId` / `versionId`，除非用户要排障或要打开某一版。来源只在返回里有 `source` 时写。

部署记录（`workflow deployments` 的 `data`，总数在信封顶层 `total`）：

```markdown
## 部署记录

共 12 条，第 1 页

| 版本 | 状态 | 成功 | 失败 | 警告 | 时间 |
| --- | --- | --- | --- | --- | --- |
| `v20261005-184620` | ✓ 成功 | 1 | 0 | 0 | 2026-10-05 18:46:20 |
```

历史版本（`workflow versions` 的 `data.data`）：

```markdown
## 历史版本

共 3 条，第 1 页

| 名称 | 草稿 | 运行中 | 说明 | 更新时间 |
| --- | --- | --- | --- | --- |
| `v20261005-184620` | 否 | 是 | 首次上线 | 2026-10-05 18:46:20 |
```

看某一版画布用 `workflow get-version`，不要把整份 `workflowJson` 贴进汇报。恢复成草稿前先问用户。
